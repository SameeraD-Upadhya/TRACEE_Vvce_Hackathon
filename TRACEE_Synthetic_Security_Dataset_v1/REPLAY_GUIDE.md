# Quick Replay Guide for TRACEE (Windows PowerShell)

This guide runs a randomized, deterministic replay sample from the supplied CSV corpus. It uses only the bundled Python standard-library adapter.

## 1. Validate the corpus

```powershell
python .\tools\tracee_csv_adapter.py validate
```

Expected output includes `"status": "PASS"` and `"total_records": 750000`.

## 2. Prepare a manageable demonstration run

This selects 5,000 rows from each of the ten source files (50,000 records total), shuffles the records reproducibly, converts each source into the correct TRACEE parser format, and interleaves the source batches in a deterministic replay queue.

```powershell
python .\tools\tracee_csv_adapter.py prepare `
  --seed 42 `
  --records-per-source 5000 `
  --batch-size 5000 `
  --output replay_runs `
  --tracee-root "D:\Hackathon\TRACEE\TRACEE"
```

The command prints a run directory such as `replay_runs\REPLAY-42-20261030T184000Z`. It also writes:

- `replay_manifest.json`: seed, dataset manifest hash, selected row counts, per-batch parser, source CSV hash, replay-order record-ID digest, batch hash and interleaved sequence.
- `compatibility_report.json`: results from the installed TRACEE parser registry.
- Parser-ready `.log`/`.jsonl` batch files arranged by source.

## 3. Upload and analyze automatically (optional)

The TRACEE API must already be running, and `TRACEE_API_TOKEN` and `TRACEE_UPLOAD_TOKEN` must be configured to the same credential (at least 32 characters). Set the client token in PowerShell:

```powershell
$env:TRACEE_API_TOKEN = "<configured-token>"
python .\tools\tracee_csv_adapter.py upload `
  --run-dir "replay_runs\REPLAY-42-20261030T184000Z" `
  --api-url "http://127.0.0.1:8000" `
  --analyze `
  --delay-min-ms 100 `
  --delay-max-ms 500
```

The adapter uploads each file as one evidence object to `POST /api/v1/evidence`, then calls `POST /api/v1/evidence/{evidence_id}/analyze` with the batch's mapped parser. It waits a seeded random 100–500 ms between batch uploads. The exact run folder name is printed by the `prepare` command; use that exact path.

Open `upload_report.json` after the command. `status: COMPLETE` means all selected batches were uploaded and all requested analyses returned success. `PARTIAL_OR_FAILED` means inspect the per-batch errors and server logs; do not assume the entire replay completed.

## 4. Full corpus run

To prepare every record (750,000 total) in batches of at most 5,000:

```powershell
python .\tools\tracee_csv_adapter.py prepare `
  --seed 20261030 `
  --records-per-source 0 `
  --batch-size 5000 `
  --output replay_runs
```

This produces 150 evidence batches. It can make the vault and chain significantly larger. Start with the 50,000-record demonstration run and verify the resulting vault before attempting the full corpus.

## 5. Important semantics

- The replay is of recorded synthetic events. It is not live telemetry collection.
- The adapter preserves original event timestamps. Replay and vault acquisition timestamps are generated by the consuming application/API.
- Do not upload the evaluation-only ground-truth file.
- Repeating the same selected batch will produce the same bytes; the current vault rejects identical SHA-256 evidence as a duplicate. Change the replay seed to select a different deterministic sample.
- The adapter can prepare and optionally upload/analyze batches, but the frontend does not yet have start/pause/resume controls or live replay status. Those are separate UI/API integration tasks.
